B. Signals (B2). Field names exactly:
- Per game: "signals": {"home_qb_changed": 0|1, "away_qb_changed": 0|1, "home_out_qb": 0|1, "away_out_qb": 0|1, "home_out_count": int, "away_out_count": int}.
  - qb_changed: the team's starting QB id for this game (games.raw home_qb_id / away_qb_id) differs from that team's starter in its previous game (across seasons; first game of a team: 0). Unknown starter for this game (empty, e.g. unplayed) means 0.
  - out_qb / out_count: injuries rows for (season, week, team, game_type REG/POST mapping as nflverse uses) with report_status = "Out"; out_qb = 1 when any Out player has position "QB". Only rows whose date_modified is before the game's decision time (kickoff minus decision_minutes_before_kickoff; when unknown, kickoff) count, to prevent leakage.
- Per team-game (team_game_stats table and feed rows): {"game_id", "season", "week", "team", "kickoff_at", "off_epa_per_play", "def_epa_per_play", "pass_rate", "plays", "success_rate"} computed from nflverse play-by-play (regular plays with an epa value; offence = posteam, defence = defteam; def_epa_per_play is EPA allowed per play).
- "team_stats" attached to a game: {"home": [rows of that team strictly before this game's kickoff, oldest first, at most 16], "away": [...]}.
- Games feed GET /api/v1/data/games body becomes {"games": [... each row gains "signals" ...], "count": n, "team_game_stats": [all rows sorted by kickoff_at, game_id, team]}. The ETag combines the games stamp with the injuries and team_game_stats stamps (count + max(updated_at)); old workers ignore the new key.
- fleet/sim/data.py: FIELDS gain "signals"; load_games attaches "team_stats" to every game from the top-level "team_game_stats" (strictly earlier kickoffs only). features_of(game) adds "signals" (dict, default all zeros) and "team_stats" (dict, default empty lists). The trade worker builds features with the same features_of on the state payload's game.
- elo_blend gains params "qb_change_penalty" (Elo points subtracted from a team whose qb_changed = 1; search space [0, 80]; default 0) and "out_penalty_per_player" (Elo points per Out player, search space [0, 15]; default 0). Applied identically in fit and predict. New search draws are appended after the existing draws so existing seeds reproduce the same earlier params.
- New family "epa_blend" (fleet/models/epa_blend.py, registered in fleet/models/registry.py): logistic regression on [elo diff/400, rolling off and def EPA diffs over the last `window` games shrunk toward the league mean by `shrink` (weight n/(n+shrink)), rest diff, qb_changed diff, out_count diff, divisional, market logit], fitted by Newton with L2 (fleet/models/newton.py: fit_logistic(rows, ys, l2, max_iter=50, tol=1e-9) -> coefficients). Search space: window int [4, 12], shrink [0, 8], l2 [0.01, 10] log-uniform, plus the betting params elo_blend searches. Pure Python.

- Worker context: a backtest with price_source snapshots gets "prices_path" in its context (fleet/worker/context.py, cached at the config's data dir like the games file, conditional GET with ETag).
- Scoring with snapshots: a game is scored only if it has a confirmed home or away market on the platform with a bar whose minute is within 30 minutes before or at the decision time (kickoff - decision_minutes). p_market for predict and for ll_market is the devigged home/away mid (close of the bar) at that minute. The bet buys the side with the larger edge at its ask; size by the same Kelly/limits as today; when depth exists within 2 minutes of the decision time, the fill walks it with book.walk at participation (settings.participation copied into limits, default 0.5), otherwise fills at the bar ask capped by participation * min_liquidity_usd_cents / (100 * ask) contracts. D. Sells (TRADING.md "Selling").
- Migration 0008_sells.sql (trading): orders.side text NOT NULL DEFAULT 'buy' CHECK (side IN ('buy','sell')); fills.basis_cents bigint (buys: price*size*100 rounded as today; sells: the basis removed); ledger.kind CHECK gains 'sell'; bets.result CHECK gains 'sold'; bets.order_side text NOT NULL DEFAULT 'buy'.
- Worker proposal (POST /api/v1/orders/request): existing body plus "order_side": "buy" (default) | "sell". The existing "side" key stays the team side (home/away) and is ignored by the host as today. client_request_id = sha256(assignment|market|snapshot_id|price|size|order_side)[:32] for sells; buys keep the old formula (no suffix) so in-flight ids do not change.
- Sell rule (fleet/worker/sell.py, called from trade.py): for each market where the assignment's position size > 0: p_side from the model; fee = taker_rate * bid * (1 - bid); sell_edge = bid - fee - p_side; if sell_edge >= min_edge propose a limit SELL at the bid for min(position size - open sell size, floor(participation * bid depth at or above the price)) contracts; never more than the position; at most one open sell per market. Stale sells: sell_edge at the current bid < 0.
- Trade state payload: markets gain "bid_depth"; open_orders gain "side"; positions are signed (buys minus sells) with {"market_id", "side", "size", "basis_cents", "avg_cost"} where avg_cost = basis_cents / (size * 100).
- Approval (host/trading/sells.py approve_sell, dispatched from limits.approve_order when order_side == "sell"): kill, lease, assignment active, market confirmed and unresolved, mode gate, stale book, participation on the bid side, price band price >= bid - 0.05, size <= position size - open sell size, one open sell per market; no reservation (orders.cost_cents 0) and no daily-loss or bankroll check; the order and its events are logged like any other. Reason codes: existing ones plus "no_position", "sell_exceeds_position", "open_sell_exists".
- Paper sell fills: walk bid levels at or above the limit with book.walk(side="sell"); a resting sell fills at its limit when a later bid crosses; participation shared per snapshot level and per side (paper fill id paper:{order}:{snapshot}:b{level} for bid levels; ask levels keep paper:{order}:{snapshot}:{level}).
- Ledger on a sell fill (host/trading/ledger.py sell()): basis = the position's remaining basis * size / remaining size, rounded to cents, and exactly the remaining basis when the sale closes the position; rows: d_open = -basis, d_available = proceeds - fee, d_realized = proceeds - fee - basis, kind "sell". The identity initial + realized = available + reserved + open still holds; replay_problems stays clean.
- Settlement: a sell order gets its own bets row (order_side "sell", result "sold", entry_price = average sell price, cost_cents = basis sold, pnl_cents = proceeds - fee - basis, clv null); each buy row covers only the contracts still held, pro rata of the remaining position per market (basis and payout split with the rounding residual on the last row so totals match the ledger), pnl = payout_remaining - basis_remaining - buy fee; the ledger settle row uses the remaining basis. model_scores.pnl includes sells; n_bets counts buys; CLV stays stake-weighted over buys.
- Kill cancels open sells like buys. Live: market_source_config.polymarket_us live block gains "side_sell": "SELL"; LiveGateway.place sends side_sell for sell orders.
- Dashboard (Trading page): a "sell" chip on sell orders and fills with realized P&L; a positions table per assignment (size, average cost, current bid, unrealized P&L at the bid).
